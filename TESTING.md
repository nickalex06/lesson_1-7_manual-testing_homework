Браузер: Google Chrome 155.0.8059.85, Windows.

Версия: `workshop-hw7.0`, исходный commit `3ba2e60`. Исправления находятся в рабочей копии.

Дата проверки: 25.10.2026.

## Условия проверки

Проверены требования R1–R8. Ошибки воспроизведены до исправлений. После каждого изменения повторены исходные шаги и проверен соседний сценарий. В Google Chrome проверены интерфейс, сохранённые данные и поведение после перезагрузки. Также проверено отображение страницы на ширине 360 px.

Сервис хранит заявки в браузере. Результат проверялся по интерфейсу и localStorage; POST-запросов в Network у этого стенда нет. Код `src/api.js` не менялся.

Перед каждым независимым сценарием: раскрыть «Условия проверки», нажать «Сбросить стенд»; исходные заявки — Анна Лебедева (HTML), Михаил Орлов и София Волкова (JavaScript). Режим обычный, фильтр «Все направления», экран 1280×900, если ниже не указано другое. Хранилище: `workshop-hw7:applications`. Данные вымышленные. После завершения стенд сброшен к трём заявкам.

## BUG-01. Валидация имени выполняется до удаления крайних пробелов

- Требование и влияние на пользователя: R1; в список попадают заявки без корректного имени.
- Условия: обычный режим, три исходные заявки.
- Данные и шаги: ввести три пробела в имя, выбрать HTML и CSS, комментарий «Проверка», нажать «Отправить заявку».
- Ожидалось: ошибка длины имени, новых заявок нет.
- Факт и свидетельство: в localStorage четыре записи, последняя `{id: "4", name: "", topic: "html", comment: "Проверка"}`.
- Исправление: `src/app.js`, `trim()` при сборе имени до `validate()`, сервис получает уже проверенные значения.
- Повторная проверка: показано «Имя должно содержать от 2 до 60 символов.», осталось три записи — пройдено.
- Соседняя проверка: имя ` Я ` отклонено; `  Яя  ` с пустым комментарием сохранено как `Яя`. Имя из 60 букв `А`, направление API и комментарий из 200 букв `Б` принимаются; 61 буква имени, 201 буква комментария, пустое и неизвестное направление отклоняются, остаются три записи. Значения сверх HTML maxlength и option `unknown` задавались через DOM для проверки обработчика, как через DevTools. Пройдено.

## BUG-02. Счётчик считает все заявки вместо видимых

- Требование и влияние на пользователя: R2; количество не соответствует отфильтрованному списку.
- Условия: обычный режим, исходные заявки, среди них нет API.
- Данные и шаги: выбрать «HTTP и API» в фильтре списка.
- Ожидалось: ноль карточек, счётчик 0, сообщение об отсутствии заявок.
- Факт и свидетельство: `.application-card` — 0 элементов, `#application-count` — `3`.
- Исправление: `src/app.js`, счётчик использует `visible.length`.
- Повторная проверка: API — 0 карточек и счётчик 0, виден пустой список — пройдено.
- Соседняя проверка: HTML — 1/1, JavaScript — 2/2, все направления — 3/3; показаны соответствующие исходные заявки. Пройдено.

## BUG-03. Клики по содержимому карточки игнорируются

- Требование и влияние на пользователя: R3; пользователь не может открыть подробности привычным кликом по тексту.
- Условия: исходные заявки, выбранной карточки нет.
- Данные и шаги: нажать на имя «Анна Лебедева» внутри первой карточки.
- Ожидалось: выбрана Анна, в подробностях её имя, направление и комментарий.
- Факт и свидетельство: `#selection-content` остался скрыт. Enter на самой кнопке работал.
- Исправление: `src/app.js`, удалена проверка `event.target !== card`; обработчик кнопки выбирает заявку и при всплытии события от её содержимого.
- Повторная проверка: клик по имени открывает Анну. Клики по теме, комментарию, номеру и стрелке также выбирают Анну — пройдено.
- Соседняя проверка: установить фокус на «Обновить», нажать Tab — фокус на карточке №1; Enter выбирает её, следующий Tab и Enter выбирают Михаила. Выбрана ровно одна карточка (`aria-pressed="true"`), подробности обновляются. Пройдено.

## BUG-04. Сброс интерфейса оставляет фильтр и выбранную карточку

- Требование и влияние на пользователя: R4; интерфейс не возвращается к исходному состоянию.
- Условия: три исходные заявки.
- Данные и шаги: выбрать Анну через Enter, установить фильтр HTML, заполнить форму «Тест Тестов» / HTML / «Проверка», нажать «Сбросить интерфейс».
- Ожидалось: пустая форма, все направления, нет выбранной карточки, три заявки сохранены.
- Факт и свидетельство: форма очищена, но значение фильтра `html`, подробности Анны видны.
- Исправление: `src/app.js`, при сбросе назначаются `selectedId = null` и `filter.value = 'all'` перед перерисовкой.
- Повторная проверка: фильтр `all`, подробности скрыты, форма очищена, три записи остались — пройдено.
- Соседняя проверка: сохранить новую корректную заявку, сбросить интерфейс и перезагрузить страницу; четыре заявки остаются. Пройдено.

## BUG-05. Основная кнопка растягивает страницу на мобильном экране

- Требование и влияние на пользователя: R5; требуется горизонтальная прокрутка для доступа ко всей кнопке.
- Условия: viewport 360×800 CSS px, обычный режим.
- Данные и шаги: открыть форму на ширине 360 px, проверить правую границу страницы и кнопки.
- Ожидалось: поля и кнопка укладываются в экран без горизонтального скролла.
- Факт и свидетельство: `document.documentElement.scrollWidth = 419`, `innerWidth = 360`; кнопка шириной 380 px, её правая граница 419 px.
- Исправление: `src/styles.css`, удалён мобильный `min-width: 380px` у `#submit-button`.
- Повторная проверка: ширина документа 360 px, кнопки 282 px; форма «Тест Тестов» / HTML / «Проверка» успешно отправляется, число записей 3 → 4. На снимке страницы: поля и кнопка внутри экрана. Пройдено.
- Соседняя проверка: при 1280×900 ширина документа также равна viewport, горизонтальной прокрутки нет. Пройдено.

## BUG-06. Повторная отправка во время ожидания создаёт дубли

- Требование и влияние на пользователя: R6; одна заявка может сохраниться дважды.
- Условия: исходные заявки, режим «Задержка 2 секунды».
- Данные и шаги: заполнить «Тест Тестов» / HTML / «Проверка», дважды быстро нажать кнопку отправки, дождаться завершения.
- Ожидалось: сохраняется одна новая заявка; после завершения доступна следующая отправка.
- Факт и свидетельство: в localStorage пять записей вместо четырёх, две новые с одинаковыми данными.
- Исправление: `src/app.js`, флаг `submitting` проверяется в начале обработчика; `setSubmitting()` согласует флаг, disabled кнопки и aria-busy. В `finally` блокировка снимается; сброс стенда также снимает её. Существующая проверка revision защищает новую отправку от завершения старой.
- Повторная проверка: двойной клик создаёт одну запись (всего 4), во время ожидания кнопка отключена; дополнительный `form.requestSubmit()` во время ожидания тоже не создаёт дубль. После ожидания кнопка доступна. Пройдено.
- Соседняя проверка: в обычном режиме «Вторая Заявка» успешно сохраняется, всего 5 записей. Отдельно: сбросить стенд во время задержки, отправить «Новая Заявка» в обычном режиме и дождаться старого ответа — остаются 4 записи с новой заявкой, кнопка доступна. Пройдено.

## BUG-07. Комментарий вставляется как HTML

- Требование и влияние на пользователя: R7; разметка меняет отображение вместо вывода введённых символов как текста.
- Условия: обычный режим, три исходные заявки; только безопасная разметка без скриптов.
- Данные и шаги: отправить «Тест Тестов» / HTML / `<b>Тест</b> & "кавычки"`; выбрать новую карточку через Enter, посмотреть подробности, перезагрузить страницу.
- Ожидалось: вся строка, включая `<b>` и `</b>`, видна буквально в карточке и подробностях, в том числе после перезагрузки.
- Факт и свидетельство: видимый текст — `Тест & "кавычки"`, в DOM появился элемент `<b>`. После перезагрузки разметка интерпретировалась снова; исходная строка в хранилище сохранялась.
- Исправление: `src/app.js`, общий `renderComment()` использует `textContent` вместо `innerHTML`, исходный комментарий не фильтруется и не меняется.
- Повторная проверка: карточка и подробности показывают точную строку; элементов `.card-comment b` — 0, localStorage содержит исходные символы. После перезагрузки и выбора карточки подробности показывают ту же строку. Пройдено.
- Соседняя проверка: заявка с пустым комментарием сохраняется и показывает «Без комментария». Обычные комментарии исходных заявок отображаются. Пройдено.

## BUG-08. Ошибка сервиса отображается как успешное сохранение

- Требование и влияние на пользователя: R8; пользователь теряет введённые данные и ошибочно считает заявку сохранённой.
- Условия: три исходные заявки, режим «Ошибка 503».
- Данные и шаги: отправить «Тест Тестов» / HTML / «Проверка», дождаться ответа.
- Ожидалось: сообщение об ошибке, форма сохраняет значения, новой записи нет, повтор доступен.
- Факт и свидетельство: «Заявка сохранена. Спасибо!», имя очищено, в localStorage по-прежнему три записи.
- Исправление: `src/app.js`, перед успехом проверяется `response.ok`; при отказе ошибка из ответа передаётся в catch, без очистки формы.
- Повторная проверка: «Сервис временно недоступен. Попробуйте ещё раз.», имя и комментарий сохранены, направление HTML осталось выбранным, записей три, кнопка доступна. Пройдено.
- Соседняя проверка: без повторного ввода переключить режим на задержку и отправить снова. Во время ожидания статус `pending`, записей три; после ответа статус `success`, записей четыре, форма очищена. Пройдено.
